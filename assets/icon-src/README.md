# 图标与头图的生成脚本

这两个脚本是**可重现的源头**：`assets/anydrag-win.ico` 与 `assets/hero.png`
不是手工调出来的二进制，跑一下就能重新生成。改设计就改这里，别直接改二进制。

```bash
# 需要 Pillow（macOS/Linux 上 python3 -m pip install pillow）
python3 assets/icon-src/build_ico.py    # → assets/anydrag-win.ico
python3 assets/icon-src/hero.py         # → assets/hero.png
```

## 为什么图标是"代码画的"而不是 AI 生图

试过 `gpt-image-2` 出图（六七个方向、二十多张），结论是**大尺寸能用、小尺寸不能用**：

- 托盘图标 99% 的时间是 **16×16**，而 16px 只有 256 个像素。两层圆角方块 + 间隙
  在这个预算下根本放不下，AI 出图缩下去必然糊成一团色块（实测 v4/v5 全部方案如此）。
- AI 图带不可控背景（黑边、云絮、渐变），而 `.ico` 必须是干净 alpha。

所以最终形态由脚本**逐尺寸独立光栅化**（8× 超采样），笔画宽度按尺寸取整到整数像素，
这是"大图缩小"做不到的。AI 探索的价值在于**选定方向**（错位双方块 / 描边虚实对比 /
中性灰），这部分记在下面的设计决策里。

## 设计决策（改之前先读）

**图形 = 两个错位圆角方块**：后层灰色细描边空心、前层白色填充 + 炭黑描边，
前层压住后层约三分之一。它表达"一个窗口叠在另一个窗口上，并且被挪动了"——
比"四向箭头"（原图标）更贴近本工具的真实语义：拖的是**窗口**，不是光标。

**为什么不额外挖间隙**：试过用橡皮擦在前层周围挖一圈透明缝，结果连带切断后层轮廓，
留下宽度不均的断口，像渲染 bug。前层本身是实心的，天然遮住后层的重叠段——
层次由遮挡关系表达就够了。

**配色**：exe 图标用中性深灰（炭黑 #2E3338 + 中灰 #9AA0A6 + 白）。
前层**必须有白色填充**：纯深灰实心在深色任务栏/深色主题下会消失（实测 16px 时
深灰块与背景同色，糊成一团）。

**托盘图标为什么仍是亮蓝**（`src/icon.rs`，与 exe 图标不同色，这是有意的）：

托盘图标是**单色剪影**（形状由 alpha 决定，没有白色填充做底），配色即状态。
实测对比度（WCAG 相对亮度）：

| 颜色 | 浅色任务栏 | 深色任务栏 |
|---|---|---|
| 炭黑 #2E3338 | 11.5:1 ✅ | **1.3:1 ❌ 几乎不可见** |
| 亮蓝 #2D7FF9 | 3.4:1 ✅ | 4.3:1 ✅ |
| 中灰 #969CA6 | 2.5:1 ⚠️ | 5.9:1 ✅ |

深灰在深色任务栏上等于隐形，而托盘图标必须"两种主题下都看得见"。
所以托盘保持亮蓝（启用）/ 中灰（禁用），exe 图标用中性深灰——
两者形状语言一致（都是"窗口"母题），配色按各自所处背景的约束选。
