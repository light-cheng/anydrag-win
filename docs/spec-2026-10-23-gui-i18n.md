## 2. 设计依据（有出处，不是拍脑袋）

调研结论（权威来源，实施时可直接引用）：

### 2.1 字体与字号

来自 [Windows Typography](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/typography)：

- Windows 11 系统字体是 **Segoe UI Variable**，备用 **Segoe UI**。
- **最小可读值：14px Semibold / 12px Regular**。"Text smaller than these sizes and
  weights are illegible in some languages."
- Windows 11 类型刻度（epx）：

  | 用途 | 字重 | 字号/行高 |
  |---|---|---|
  | Caption | Small | 12/16 |
  | Body | Text | **14/20** |
  | Body Strong | Text Semibold | 14/20 |
  | Body Large | Text | 18/24 |
  | Subtitle | Display Semibold | **20/28** |
  | Title | Display Semibold | 28/36 |

- **Casing：Sentence case**（句首大写），标题也一样。
- **不要用 Bold/Italic**，强调用 **Semibold**。Italic 降低可读性（尤其阅读障碍者）。

→ 本 SPEC 取值：正文 **14px Regular**、卡片标题 **14px Semibold**、窗口副标题
**12px Regular**、窗口主标题 **20px Semibold**。**当前 12px 正文与 15px 标题都偏小/不合刻度**。

- 中文字体：简体用 **Microsoft YaHei UI**（同页 Languages 表明确列出），
  西文用 Segoe UI。用 `CreateFontW` 的 `lfFaceName` 写 `"Microsoft YaHei UI"`
  会把英文也画成雅黑（可接受，但字形不如 Segoe）；更好的做法是**字体链接**
  （`lfFaceName = "Segoe UI"` + 系统自动 fallback 到雅黑渲染汉字）——Windows 的
  font linking 默认已配好，直接写 Segoe UI 即可正确显示中文。**实测确认后再定**。

### 2.2 颜色与主题

来自 [Color in Windows](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/color)：

- 浅色/深色两套中性色，**对比度必须足够**。
- 强调色（accent）**只用于强调交互元素**，"Use color sparingly"。
- 无障碍：约 8% 男性 / 0.5% 女性红绿色盲，**不能只用颜色区分状态**。

→ 本 SPEC：
- 当前"卡片标题用蓝色 `#2D7FF9`"违反"accent 只用于交互元素"——卡片标题不是可点的。
  改为：卡片标题用正文色（`#1A1A1A`），**accent 只留给主按钮和焦点环**。
- 平台规范要求支持深浅色。**本 SPEC 的取舍见 §6 决策 D2**。

### 2.3 深色主题：**实测结论**（不是推测）

2026-10-23 用探针实测（探针已删，方法记录在此）：

- 建一个窗口：`DwmSetWindowAttribute(DWMWA_USE_IMMERSIVE_DARK_MODE, 1)` + 深色自绘背景，
  里面放 EDIT / CHECKBOX / BUTTON / STATIC 各一。
- 分三种配置截屏对比：
  - `plain`：只设 DWM 深色标题栏（= **当前实现的做法**）
  - `theme`：额外 `SetWindowTheme(h, "DarkMode_Explorer", NULL)` + `AllowDarkModeForWindow(h, 1)`
  - `force`：`theme` + `SetPreferredAppMode(2)`（uxtheme 未文档化导出）

实测结果（截图见 `docs/spec-assets/dark-experiment-plain.png` 与
`dark-experiment-theme.png`）：

| 控件 | `plain`（现状） | `theme` | `force` |
|---|---|---|---|
| 窗口底（自绘） | 深 ✅ | 深 ✅ | 深 ✅ |
| `EDIT` | **白底黑字 ❌** | **深底浅字 ✅** | 同 theme |
| `BUTTON` | **白底黑字 ❌** | **深底浅字 ✅** | 同 theme |
| `CHECKBOX` | **白底 ❌** | **白底浅字，比 plain 更糟 ❌** | 同 theme |
| `STATIC` | **白底黑字 ❌** | **白底黑字 ❌** | 同 theme |

**结论（三条，都是实测而非推断）**：

1. `SetWindowTheme(..., "DarkMode_Explorer")` **确实有效**，能让 EDIT 与 BUTTON 跟随深色。
   我原先在 SPEC 里写"原生控件不跟随深色、硬做会撕裂"是**只对了一半**——准确说法是
   "EDIT/BUTTON 能跟随，CHECKBOX/STATIC 不能"。
2. **`SetPreferredAppMode(2)` 与 `(1)` 没有任何额外效果**，不必用它（还多一个未文档化依赖）。
3. **CHECKBOX 是硬骨头**：套了 `DarkMode_Explorer` 之后它是**白底 + 浅色文字**，
   可读性比不套主题更差。STATIC 则完全不变。

**因此深色主题的正确做法**（本 SPEC 采用）：

- 对 `EDIT` / `BUTTON` 用 `SetWindowTheme(h, "DarkMode_Explorer", NULL)` —— 零成本拿到原生深色。
- 对 `CHECKBOX` / `STATIC`（以及卡片标题等自绘元素）**全部改为自绘**：
  - STATIC → 不用 STATIC，直接在 `paint_background` 里 `TextOutW`（本来就该这样，
    当前用 STATIC 是为了省事）。
  - CHECKBOX → `BS_OWNERDRAW` + 处理 `WM_DRAWITEM`，自己画方框与勾，颜色取自主题。
    这是唯一能让复选框在深浅两种主题下都可控的办法。
- 主题判定：读 `HKCU\...\Themes\Personalize\AppsUseLightTheme`（0 = 深色）。
  **注意本沙箱曾拦注册表**（AGENTS 坑 #9），但那是 `reg.exe` 与 PowerShell provider；
  进程内 `RegGetValueW` 不受影响，需实测确认。
- 监听主题变化：`WM_SETTINGCHANGE` + `lParam == "ImmersiveColorSet"` 时重取并重绘。

> **代价说明**：CHECKBOX 自绘是本次工作量最大的一块（约 120-150 行 + 焦点框 +
> 键盘空格切换 + 禁用态 + 高对比度兜底）。若时间紧，**允许降级方案**：
> 深色下把复选框的**背景**画成卡片同色（深）而方框与文字用浅色，
> 用 `BS_OWNERDRAW` 只画这一个矩形 + 文字，不做完整 owner-draw 控件。
> 但**不许**保持"白底浅字"这种不可读状态上线。

## 3. 目标设计

### 3.1 信息架构

把现在"3 张卡片 + 卡片外游离标签"重排为**4 组**，顺序按"用户最常改的在前"：


### 3.3 控件选择

| 需求 | 方案 | 理由 |
|---|---|---|
| 复选框 | **`BS_OWNERDRAW` + `WM_DRAWITEM` 自绘** | 见 §2.3：原生 CHECKBOX **不能**跟随深色（白底浅字，比不套主题更糟）。自绘是唯一能让深浅两种主题都可控的办法 |
| 数字输入 | `EDIT` + `ES_NUMBER` + `WS_EX_CLIENTEDGE` + 深色下 `SetWindowTheme(h,"DarkMode_Explorer")` | §2.3 实测：EDIT 能跟随深色 |
| 单位后缀 | **自绘文字**（`paint_background` 里 `TextOutW`），不用 STATIC | §2.3 实测：STATIC 不跟随深色 |
| 所有说明性文字 | **自绘**（`TextOutW`），不用 STATIC | 同上 |
| 语言切换 | 两个 `BS_AUTORADIOBUTTON \| BS_PUSHLIKE`，**深色下自绘或改用自绘分段按钮** | `BS_PUSHLIKE` 是 BUTTON 家族，§2.3 实测 BUTTON 能跟随深色 —— 可先试原生；若实际观感不对再自绘 |
| 卡片标题 / 卡片背景 | 自绘（`paint_background` 已有机制） | 已有，沿用 |
| 主按钮 | `BS_DEFPUSHBUTTON` + `DarkMode_Explorer` | 已有；BUTTON 能跟随深色 |

**为什么不再"全部坚持原生"**：§2.3 的实测推翻了原先的假设。原生 CHECKBOX/STATIC
在深色下**不可读**，不是"观感差一点"而是"看不见"。所以：

- **能跟随的原生控件继续用原生**（EDIT / BUTTON）——省掉自绘的焦点框、键盘、无障碍。
- **不能跟随的两类改自绘**（CHECKBOX / 全部静态文字）——否则深色模式根本不能用。

自绘 CHECKBOX 必须覆盖的行为（缺一个就是残废控件）：

| 行为 | 实现要点 |
|---|---|
| 鼠标点击切换 | `WM_DRAWITEM` 不负责点击；靠 `BS_OWNERDRAW` 的 `BN_CLICKED` 通知，自己维护勾选状态 |
| 键盘空格 | 控件获得焦点时 `VK_SPACE` → 同样触发 `BN_CLICKED`（原生 BUTTON 自带，owner-draw 仍有） |
| 焦点框 | `ODS_FOCUS` / `ODS_SELECTED` 标志 → 画虚线框或 accent 描边 |
| 禁用态 | `ODS_DISABLED` → 文字与方框降不透明度 |
| 高对比度 | 系统高对比度下**不该自绘**（会丢失用户配色）→ 检测到高对比度时退回原生外观 |
| 勾选状态存储 | 不能再用 `BM_GETCHECK`（owner-draw 的 BUTTON 不维护它）→ 自己用 `Vec<bool>` 或 `SetWindowLongPtr` 存在控件里 |

> 这一块是本 SPEC 工作量最大、最容易出 bug 的地方。**建议先只做"能勾选 + 能读回 +
> 深浅两种主题都读得清"这三条**，焦点框与高对比度可以第二轮补，但要在
> `AGENTS.md` 留 TODO。

### 3.4 深色主题：**要做，跟随系统**（见 §2.3 实测与 §6 决策 D2）

**配色以 §2.4.6 为准**（那是从 DSH 实测令牌里取的），不再另立一套。
这里只列"怎么落地"：

| 用途 | 浅色 | 深色 | 实现方式 |
|---|---|---|---|
| 窗口底 | `#f5f6f7` | `#151517` | 自绘 `FillRect` |
| 卡片 | `#ffffff` | `#232324` | 自绘 `RoundRect` |
| 卡片边框 | `#0000000a` | `#ffffff0f` | 自绘 `RoundRect` 的 pen（alpha 边框） |
| 主文字 | `#0f1115` | `#f9fafb` | 自绘 `TextOutW` |
| 次文字 | `#61666b` | `#cfd3d6` | 自绘 `TextOutW` |
| 输入框 | 由 `DarkMode_Explorer` 处理 | 同左 | `SetWindowTheme` |
| 复选框 | 自绘 | 自绘 | `BS_OWNERDRAW` + `WM_DRAWITEM` |
| 焦点环 | `#4176E6` | `#7AAAFF` | 自绘 2px 描边 |

> **GDI 画 alpha 的坑**：`RoundRect`/`FillRect` 的画笔与画刷**不吃 alpha**
> （`COLORREF` 没有 alpha 通道）。DSH 的 `#0000000a` 这类半透明边框在 GDI 里
> 必须**先按背景色预混合成实色**再画。例如浅色卡片 `#ffffff` 上画 `#0000000a`：
> 实际输出 `#f5f5f5` 左右。写代码时用一个 `blend(fg_alpha, bg)` 辅助函数算实色，
> 不要直接把 alpha 塞进 `COLORREF`（会被忽略，边框变成纯黑，非常难看）。
> 或者改用 `GdiPlus`（支持 alpha），但那要引 `GdiplusStartup`，成本更高。
> **建议**：预混合成实色，简单可靠。

主题判定与跟随：

```rust
// winmod.rs
/// 系统是否使用深色应用主题（读 HKCU\...\Themes\Personalize\AppsUseLightTheme，0 = 深色）。
pub fn system_dark_mode() -> bool
```

- 读不到（键不存在/被拦）→ **按浅色处理**，不报错。
- `WM_SETTINGCHANGE` 且 `lParam` 指向 `"ImmersiveColorSet"` 时重取并 `InvalidateRect` 全窗重绘。
  同时要**对已有控件重新 `SetWindowTheme`**（EDIT/BUTTON 的主题切换不会自动发生）。

### 4.2 配置

`config.rs` 的 `Config` 新增字段（`#[serde(default)]` 已在整个 struct 上，旧配置自动兼容）：

```rust
/// 界面语言："" = 跟随系统（首次运行/旧配置），"zh" / "en" = 用户显式选择。
pub lang: String,
```

默认 `String::new()`（= auto）。

**为什么存字符串而不是枚举**：`Config` 是 serde 反序列化的对外格式，存 `"zh"`/`"en"`
比存数字可读、手改配置不易错，也与既有 `native_excluded` 风格一致。枚举解析失败时
`Lang::from_config` 已有 fallback。

### 4.3 系统语言检测

`winmod.rs` 增加：

```rust
/// 系统 UI 语言是否中文（GetUserDefaultUILanguage 的主语言 ID == 0x04）。
pub fn system_is_chinese() -> bool
```

`GetUserDefaultUILanguage()` 返回 LANGID；`LANGID & 0x3FF == 0x04` 表示中文
（简体 `0x0804`、繁体 `0x0404`/`0x0C04` 都命中）。**注意 DPI 不变量 1 与本函数无关**
（它不是第一个 FFI 调用，`dpi_aware_v2()` 仍是）。

### 4.4 生效时机

| 场景 | 行为 |
|---|---|
| 设置界面点语言按钮 | **立即重绘全部文案**（不重建窗口），并写入内存 `config::replace()` |
| 点"保存" | 写盘，下次启动沿用 |
| 点"取消" | **回滚**到打开窗口时的语言（与其它字段一致：取消不保存） |
| 手改 `config.json` 的 `lang` | 下次打开设置窗口生效（托盘 tooltip/菜单在下次点击时重取） |

**实现要点**：语言切换时遍历已知控件句柄 `SetWindowTextW`，再 `InvalidateRect`
重绘卡片标题（标题是自绘的）。**不要 `DestroyWindow` + 重建**——会丢失用户已输入但
未保存的其它字段，也会让窗口闪烁。

> 需要一个 `retranslate(hwnd)` 函数：从 `Ctls` 里取每个句柄 → `SetWindowTextW(tr(...))`。
> 同时更新窗口标题（`WM_SETTEXT`）。

## 6. 关键决策与取舍（已定，勿擅自更改）

### D1 不引 GUI 框架 —— 见 §1.2

### D2 **做深色主题，跟随系统**（2026-10-23 用户明确要求，推翻上一版）

**上一版决策是错的，且错在"没验证就下结论"**：我原先写"原生控件不跟随深色、
硬做会撕裂"并据此禁用。实测（§2.3）证明准确情况是：

- `SetWindowTheme(h, "DarkMode_Explorer", NULL)` **确实有效**，EDIT 与 BUTTON 能跟随深色；
- CHECKBOX 与 STATIC **不能**，而且套主题后 CHECKBOX 变成"白底浅字"，
  比不套**更糟**；
- `SetPreferredAppMode(2)` 与 `(1)` 无差别，不必用。

所以做法是**混合**，不是"全原生"也不是"全自绘"：

| 控件 | 方案 |
|---|---|
| EDIT / BUTTON | 原生 + `SetWindowTheme` |
| CHECKBOX | `BS_OWNERDRAW` 自绘（含焦点环、键盘空格、禁用态） |
| 所有静态文字 | 自绘 `TextOutW`（不用 STATIC） |
| 卡片 / 背景 / 分隔线 | 自绘（已有机制） |

**主题判定**：`winmod::system_dark_mode()` 读 `AppsUseLightTheme`；读不到按浅色。
**跟随变化**：`WM_SETTINGCHANGE` + `lParam == "ImmersiveColorSet"` 时重取并全窗重绘 +
对已有 EDIT/BUTTON 重新 `SetWindowTheme`。

**教训（要写进 AGENTS.md）**：把"某平台能力做不到"当结论之前**必须实测**。
本次因为没实测，白写了一版错误的 SPEC，还差点让实现者绕开一个其实可用的 API。

### D2b 视觉令牌取自 DSH，不自行设计

用户明确说"DSH 的样式就很好看"。所以配色、圆角、焦点环全部照 §2.4 的实测令牌，
**不自己调色**。自行发挥的结果就是现在这个"丑"的界面。

若某个值在 Win32/GDI 下无法表达（如 alpha 边框），按 §3.4 的说明**预混合成实色**，
不要退回硬编码纯色。

### D3 语言切换不重建窗口，只 `SetWindowTextW` + 重绘

理由见 §4.4：重建会丢用户未保存的输入。

### D4 文案统一走 `i18n::tr`，禁止在 `settings.rs`/`tray.rs` 里硬编码任何用户可见字符串

**这是硬约束**（坑 #18 的直接应用）。实施时若发现某处确实无法接入（例如
`MessageBoxW` 的标题），也必须从 `tr()` 取。

### D5 英文文案优先照顾"能装进布局"

英文普遍比中文长 1.5–2 倍。写英文文案时以"150px 标签列能放下"为准，宁可拆成
"标签 + 单位后缀"，不要写长句。见 §3.2 的动因说明。

## 7. 实施顺序（建议）

**第 0 步（先做，风险最高）**：把主题与令牌落成一个可运行的"配色+度量"模块。

   （§2.4.6 全部值）、`blend(fg_alpha, bg) -> COLORREF` 预混合函数、
   `radius`/`font` 常量。**纯逻辑、可单测**（`blend` 有明确数学期望，值得测）。
2. `winmod::system_dark_mode()` 读 `AppsUseLightTheme`；读不到返回 `false`（浅色）。
3. **先量后改**：把 `settings.rs` 现有布局参数提成 `LAYOUT` 常量表。
   这一步不改行为，`cargo test` + 截图确认外观没变（对照组）。
4. `i18n.rs` 定稿：按 §3.1 分组重排 `Key`，补齐中英文案，跑单测。
5. `config.rs` 加 `lang` 字段 + 单测（旧配置缺字段能加载）。
6. `winmod::system_is_chinese()`（LANGID & 0x3FF == 0x04），实机确认默认语言。
7. **自绘 CHECKBOX**（最大工作量，单独一步）：`BS_OWNERDRAW` + `WM_DRAWITEM`，
   含勾选状态自管、键盘空格、焦点环、禁用态、高对比度退回原生。

8. `settings.rs` 重排布局 + 换字体 + 语言分段按钮 + `retranslate()` + 深色落地

9. `WM_SETTINGCHANGE` 跟随系统主题切换。
10. `tray.rs` 接 i18n（菜单、tooltip、用法弹窗）—— **必做，见 §4.5**。
11. 截图验收（§5.2，**四张**：中/英 × 浅/深），放进 `docs/spec-assets/`。
12. 更新文档：`AGENTS.md`（新坑：DSH 令牌来源、GDI alpha、`PrintWindow` 抓不到子控件、
    "未实测就下结论"的教训）、`README.md`（语言切换 + 深色主题说明）、
    `docs/testing.md`（新增设置界面外观验收 §5.4）。

## 8. 风险与已知坑（实施前必读）

| 风险 | 说明 | 对策 |
|---|---|---|
| R1 布局随语言变长而崩 | 英文比中文长，容易把输入框挤出窗口 | 窗口宽度按**英文**量；`§5.2 V6` 强制截图核对 |
| R2 字体链接 | 写 `Segoe UI` 时中文靠系统 font linking 落到雅黑。**若某机器上汉字变成方块**，改 `lfFaceName` 为 `Microsoft YaHei UI` | 实测 144 DPI 下的中文截图 |
| R3 `CreateWindowExW` 同步触发 `WM_CREATE` | 坑 #15：在 `WM_CREATE` 里存句柄时，外层赋值可能还没执行 | 沿用现有的"拆两个静态"写法 |
| R4 跨进程读控件被 UIPI 过滤 | 坑 #16：外部脚本读不到 EDIT 内容，验证必须用 `SendMessageTimeoutW(WM_GETTEXT)` 或进程内验证 | 验收脚本别用 `GetWindowTextW` 读别的进程 |
| R5 `BM_CLICK` 是**切换**不是"设为勾选" | 上一轮实测踩过：想把复选框设为未勾选，结果把未勾的勾上了 | 验收脚本先 `BM_GETCHECK` 再决定点不点 |
| R6 低完整性标签 | 坑 #19：从工作区启动的 exe 是 Low IL，托盘装不上、探针注入无效 | 复制到 `%TEMP%` 并 `icacls /setintegritylevel Medium` |
| R7 测试数变化 | AGENTS/README/testing.md 都写了 57 | 改动后**同步三处**，且别用 `grep -c '#[test]'`（坑 #20） |
| R8 GDI 不吃 alpha | `COLORREF` 无 alpha 通道，DSH 的 `#0000000a` 边框直接塞进去会被忽略 → 变成纯黑粗线 | 用 `blend(fg, alpha, bg)` 预混合成实色（§3.4） |
| R9 `SetWindowTheme` 需要 `Win32_UI_Controls` feature | 本仓 `Cargo.toml` 未启用 | 推荐加 feature（它是文档化 API）；或 `LoadLibrary`+`GetProcAddress` |
| R10 `GetProcAddress` 只吃 ANSI 名字 | 实测传 UTF-16 指针恒返回 NULL，曾误判"API 不存在" | 传 `b"Name\0"` 而非 `wstr()` |
| R11 自绘 CHECKBOX 丢 `BM_GETCHECK` | owner-draw 的 BUTTON 不再维护勾选位，`populate`/`collect` 会读不到 | 自己维护状态并改写 `populate`/`collect` |
| R12 `PrintWindow` 抓不到子控件 | 实测只画背景，子控件空白；`GetDC(hwnd)+BitBlt` 同样 | 验收截图必须用**屏幕截屏**（`CopyFromScreen`）且窗口置顶 |
